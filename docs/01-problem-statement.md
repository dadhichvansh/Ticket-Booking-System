# 01 - Problem statement

Ticket buyers want to book seats for popular events where demand far exceeds supply, and thousands of them may try to book the same seats at the same moment. The hard part is that these concurrent requests conflict: without careful control, the system can sell one seat to two people, or take a user's payment without giving them a seat. This system must never double-book a seat, and must never confirm a payment without a seat or a seat without a payment, even under heavy load or partial failure. When a user selects a seat, it is held for them for a short time. The hold is released if they abandon it, release it themselves, or the time runs out, and a failed payment does not release it immediately, so the user can retry. Buyers can also cancel a confirmed booking. The system must refund a cancelled booking exactly once and never release a seat without a valid cancellation. The system should also stay responsive and available during demand spikes. When there are more buyers than seats, users who don't get a seat should be told quickly and clearly, rather than waiting and then failing.
